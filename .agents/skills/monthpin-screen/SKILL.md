# 몬스핀 화면 추가·수정

공통 규칙은 [AGENTS.md](../../../AGENTS.md)를 따르고, 현재 화면 동작과 구조는 [README](../../../README.md)의 관련 절을 확인한다. 이 스킬은 화면 작업의 수행 절차를 다룬다.

## 기존 화면과 변경 범위 확인

- 요청한 화면과 비슷한 화면·입력 폼을 찾아 진입 경로, 저장 후 닫힘·이동, 목록 갱신 흐름을 확인한다.
- 재사용 후보는 `src/components/ui.tsx`, `typography.tsx`, `form-select.tsx`, `form-segments.tsx`에서 필요한 것만 읽는다. 화면 데이터의 연결이 바뀌면 `src/hooks/`의 관련 훅까지 추적한다.
- UI 구성·조작 변경의 선택지와 추천안을 정리하고 AGENTS.md의 협의 기준을 적용한다. 합의가 필요한 부분은 답변 전 구현하지 않으며, 기존 합의나 단순 오류 복구에는 불필요한 재확인을 추가하지 않는다.

## 화면 구현

- 기존 입력 폼과 상태 관리 흐름에 변경을 연결하고, 저장 성공·실패 시 화면 상태와 목록 갱신이 어떻게 이어지는지 확인한다.
- 새 화면이라면 진입·뒤로 가기 경로를 연결한다. 기존 화면 수정이라면 현재 진입 경로와 관련 화면의 영향을 함께 확인한다.
- 비동기 조회나 저장을 다룰 때는 해당 화면에 필요한 로딩·빈 상태·오류·재시도와 중복 제출 처리를 구현한다.
- 화면 전환이나 선택 월 변경 중 늦게 도착한 조회 결과가 현재 화면을 덮어쓰지 않는지 확인한다. 단순 문구·스타일 수정에 조회 구조 변경까지 확대하지 않는다.

## 작업에 맞는 확인

- 변경한 사용 흐름을 진입 → 입력·선택 → 저장 또는 취소 → 결과 반영까지 확인한다. 실패 처리가 바뀌었다면 실패 후 재시도도 확인한다.
- 폼·모달·선택 UI가 바뀌면 작은 화면, 긴 표시명, 키보드와 하단 버튼의 겹침, 스크롤·닫기 동작을 확인한다. 조작 요소의 접근성 이름과 선택·비활성 상태도 확인한다.
- iOS·Android에서 차이가 날 수 있는 동작은 가능한 환경에서 확인하고, 기기나 실행 환경이 없으면 확인하지 못한 항목을 완료 보고에 명시한다.
- 계산·검증·조회 상태 로직도 바뀌었다면 관련 기존 테스트를 실행하고 필요한 회귀 검증을 보완한다. 단순 문구·스타일 수정에 구현을 그대로 따라 쓰는 테스트는 추가하지 않는다.
- AGENTS.md의 공통 완료 기준을 적용하고, 결과에 합의한 화면 동작과 확인 범위를 설명한다.
