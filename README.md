# MonthPin

매달 나가는 고정비와 결제수단을 관리하는 Expo / React Native 앱입니다.

## 아이폰에서 실행하기

프로젝트 폴더에서 실행합니다. 이미 실행 중인 Expo 터미널은 Ctrl+C로 종료하고 다시 시작해 주세요.

```sh
npx expo start --go --clear
```

아이폰과 컴퓨터를 같은 Wi-Fi에 연결한 뒤 카메라로 QR 코드를 스캔하고 Expo Go로 엽니다.

1. **결제수단**에서 통장 또는 카드를 등록합니다.
2. **고정비**에서 이름, 월 금액, 결제일과 결제수단을 입력합니다.
3. **홈**에서 월 합계와 다가오는 결제 일정을 확인합니다.

항목을 누르면 상세 정보를 볼 수 있고 수정·삭제할 수 있습니다. 처음 실행하면 빈 목록으로 시작합니다.

## IntelliJ에서 실행하기

`Run → Edit Configurations → + → npm`에서 실행 설정을 추가합니다. 기존 `start` 스크립트를 사용하므로 별도 실행 스크립트를 추가할 필요는 없습니다.

| 설정 | 값 |
| --- | --- |
| Name | `MonthPin Expo Go` |
| package.json | 프로젝트 루트의 `package.json` |
| Command | `run-script` |
| Scripts | `start` |
| Arguments | `-- --go --clear` |
| Node runtime | 설치된 Node.js 22.13 이상 |
| Package manager | `npm` |

설정을 저장한 뒤 ▶ 버튼으로 실행합니다. 재실행할 때는 ■ 버튼으로 종료한 뒤 ▶ 버튼을 누릅니다. 실행 중인 다른 개발 서버가 있다면 먼저 종료해 주세요. 아이폰에서는 같은 Wi-Fi에 연결하고 Expo Go로 QR 코드를 스캔합니다. 이 설정은 컴퓨터의 개발 서버 실행을 위한 것이며, 앱의 기존 저장 데이터는 유지됩니다.

## 현재 구현 범위

- 홈 / 고정비 / 결제수단 / 설정 하단 탭
- 고정비 등록·수정·삭제와 선택적인 결제수단 연결
- 은행·통장 별명, 카드사·카드 이름, 카드 대금 출금 통장·출금일
- 통장·카드 등록 및 수정 시 주요 은행 10곳·카드사 9곳 선택 목록과 기관별 색상·약칭 아이콘
- 결제수단 목록의 ‘순서 변경’에서 오른쪽 손잡이를 드래그해 이동, 통장·카드별 순서 저장
- 이름·기관·월 고정비 중심의 간결한 목록, 카드의 출금 정보를 한 줄로 표시
- 카드 대금을 내는 통장 기준의 고정비 합계와 중복 없는 전체 합계
- 29~31일이 없는 달은 월말로 표시하는 예상 결제 일정
- SQLite 기기 저장: 앱 재시작 후에도 유지

서버, 계정 로그인, 자동 금융 연동, 알림, 별도 백업, 기기 간 동기화는 구현하지 않았습니다. 앱 삭제나 앱 데이터 초기화 시 데이터가 사라질 수 있습니다. Expo Go에서 저장한 데이터는 해당 개발 프로젝트의 데이터이며, 추후 스토어 앱으로 자동 이전되지는 않습니다.

현재 저장 방식은 iOS·Android를 대상으로 합니다. SQLite의 웹 실행 설정은 별도로 구성하지 않았습니다.

은행·카드사 목록은 `src/data/providers.ts`에서 관리합니다. `bank_kb`, `card_samsung` 같은 앱 내부 고정 코드는 공식 금융기관 코드와 별개이며, 기관 이름을 변경해도 코드는 유지해야 합니다. DB에는 기관 목록을 `payment_providers`로 관리하고, 결제수단은 `providerCode`로 참조합니다. 새 등록과 수정은 목록 선택만 허용합니다.

DB 버전 1의 기존 기관명은 버전 2로 자동 이전합니다. 알려진 이름·약칭은 기관 코드로 연결하고, 매칭되지 않는 이름은 기존 기록과 연결을 보존하기 위해 `legacyProvider`에 남깁니다. 해당 기록을 수정할 때는 지원하는 기관을 선택해야 합니다. 이전 과정은 트랜잭션으로 처리하며 고정비·출금 통장 연결과 기존 ID를 유지합니다.

DB 버전 3에서는 결제수단에 `sortOrder`를 추가합니다. 기존 통장·카드별 표시 순서는 유지하고, 새 항목은 해당 목록 맨 아래에 추가합니다. ‘순서 변경’을 누른 뒤 오른쪽 손잡이를 잡고 이동하면 항목이 살짝 확대되고, 화면 가장자리에서는 목록이 자동으로 스크롤됩니다. 놓으면 즉시 저장되며 ‘완료’는 편집 모드를 종료합니다. 저장에 실패하면 이전 순서로 돌아갑니다. 순서는 이름 수정·다른 탭 전환·앱 재시작 후에도 유지됩니다.

## 파일 구조

앱의 시작점은 `expo-router/entry`입니다. 예전 `App.tsx` 대신 아래 화면 파일을 수정합니다.

- `src/app/(tabs)/`: 홈, 고정비, 결제수단, 설정 화면과 하단 탭
- `src/app/_layout.tsx`: 앱 공통 설정과 데이터 저장 초기화
- `src/components/`: 공통 화면 구성과 입력 폼
- `src/data/`: 데이터 모델과 SQLite 읽기·쓰기
- `src/hooks/`: 화면에 데이터를 공유하는 상태 관리
- `src/utils/`: 합계, 날짜 계산, 입력 검증

나중에 백엔드를 추가할 때는 화면과 분리된 데이터 읽기·쓰기 부분부터 변경할 수 있습니다.

## 공통 코드와 데이터 설계 기준

앞으로 추가하거나 수정하는 기능은 서버·DB 확장을 고려해 다음 기준을 기본으로 적용합니다. 저장 값은 UI 컨트롤 모양보다 데이터의 의미를 기준으로 결정합니다.

- **공통 선택 항목:** 셀렉트박스·라디오·체크박스에서 은행, 카드사, 유형, 상태 등 미리 정의된 항목을 선택할 때는 고정 코드를 저장합니다. 화면 표시명, 배열 순번, 번역된 문구를 저장 값으로 사용하지 않습니다.
- **단순 flag:** 사용 여부, 알림 켜짐처럼 참·거짓만 의미하는 값은 `boolean`을 사용합니다. SQLite에서는 `0/1`로 저장하고 데이터 읽기·쓰기 계층에서 변환합니다. 여러 상태를 나타내는 값은 코드로 관리합니다.
- **사용자 데이터 선택:** 직접 등록한 통장·카드 등 사용자마다 다른 항목은 해당 레코드의 ID로 참조합니다. 현재 `bankId`, `methodId`처럼 관계를 저장하고 DB에서 외래 키로 검증합니다.
- **다중 선택:** 여러 공통 항목을 선택하는 체크박스는 코드 배열로 표현합니다. DB에서는 필요에 따라 연결 테이블로 관리하고, 쉼표로 합친 표시명이나 배열 순번으로 저장하지 않습니다.
- **이름 규칙:** 코드 값은 소문자 `snake_case`를 사용합니다. 예: `bank_kb`, `card_samsung`, `bank`, `card`. 코드 목록 상수는 `BANK_PROVIDERS`처럼 대문자 `UPPER_SNAKE_CASE`를 사용합니다. 모델 필드명은 기존처럼 `providerCode`, `bankId` 등 `camelCase`를 유지합니다.
- **한곳에서 관리:** 코드·표시명·아이콘 정보는 `src/data/`의 도메인별 목록에서 관리하고, 화면은 해당 목록을 사용합니다. TypeScript 타입도 목록에서 유도하거나 공통 타입으로 정의해 허용 값을 제한합니다. 저장 시 지원하는 코드와 해당 분류가 맞는지 검증합니다.
- **서버·DB 연동:** 기관 같은 공통 목록은 코드 테이블과 외래 키로, 작은 고정 유형은 제약 조건으로 검증합니다. 추후 서버가 공통 목록을 제공하면 서버를 기준으로 목록을 관리하고, API·앱·DB가 같은 코드 값을 사용하도록 연결합니다.
- **기존 데이터 유지:** 표시명·아이콘 변경 시 코드는 유지합니다. 저장된 코드의 변경·삭제가 필요하면 데이터 이전과 기존 참조 처리를 함께 구현합니다. 미지원 코드가 들어와도 임의의 기본 코드로 바꾸지 않고 기존 값을 보존해 처리합니다.

현재 은행·카드사는 `src/data/providers.ts`와 `payment_providers`에서 이 방식으로 관리합니다. 위 규칙은 향후 개발 기준이며, 아직 없는 서버 API나 새 기능이 구현되었다는 의미는 아닙니다.

기능 변경 시 대체된 코드·스타일·가져오기와 실제로 사용하지 않게 된 라이브러리를 함께 정리합니다. 다른 기능이나 의존성에서 필요한 라이브러리는 유지합니다. UI 구성이나 조작 방식이 달라지는 작업은 구현 전에 선택지와 추천 구성을 설명하고 사용자와 방향을 정합니다.
