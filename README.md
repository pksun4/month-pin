# MonthPin

매달 나가는 고정비와 결제수단을 관리하는 Expo / React Native 앱입니다.

## 앱 로고와 아이콘

동전·핀 심볼을 앱 브랜드로 사용합니다. 홈 화면에서는 배경 없는 파란 심볼(높이 26)을 MonthPin 이름 왼쪽에 표시합니다. 이름은 앱 공통 글꼴인 Pretendard ExtraBold(800), 크기 28·자간 -0.3이며 심볼과의 간격은 7로 중심을 맞춥니다. 앱 아이콘과 웹 파비콘에는 기존 파란 배경·흰색 심볼을 유지합니다.

- `assets/brand/logo-source.png`: 사용자가 선택한 원본 시안. 내장 이미지 생성 도구로 제작했으며, 프롬프트는 ‘파란 배경·흰색 둥근 핀을 유지하고 안쪽을 두께와 겹침이 보이는 동전 세 개로 표현; 문자·통화 기호·반사선 없이 구성’입니다.
- `assets/brand/symbol-source.png`: 내장 이미지 생성 도구로 편집한 홈 심볼 원본. 프롬프트는 ‘선택한 동전·핀의 형태를 유지하고 흰 심볼을 파란색으로 변경; 배경·내부 여백은 투명 처리; 문자·장식 추가 없이 구성’입니다.
- `assets/brand/symbol.png`: 화면용 투명 224×256 이미지. 실제 표시 영역에 맞게 바깥 여백을 줄이고, 앱의 공통 파란색으로 표시합니다.
- `assets/icon.png`: iOS·Android 아이콘용 1024×1024 이미지; Android 적응형 아이콘도 이 이미지를 사용합니다.
- `assets/favicon.png`: 웹 파비콘용 64×64 이미지

같은 동전·핀 디자인을 사용처에 맞게 내보냈습니다. 이미지는 앱과 함께 포함되어 오프라인에서도 표시됩니다. Android의 예전 템플릿 배경·단색 아이콘 설정과 사용하지 않는 홈 배지 이미지는 제거했습니다.

앱 안의 로고는 개발 앱을 다시 불러오면 확인할 수 있습니다. 휴대폰 홈 화면의 아이콘은 개발 빌드·배포 앱을 새로 빌드해야 반영됩니다. Expo Go 자체의 아이콘은 변경되지 않습니다. [Expo 앱 아이콘 안내](https://docs.expo.dev/develop/user-interface/splash-screen-and-app-icon/)

## 글꼴

로고 이름과 화면의 한글·영문·금액·입력칸·하단 메뉴는 모두 [Pretendard](https://github.com/orioncactus/pretendard)로 표시합니다. MonthPin 이름은 ExtraBold(800)·크기 28·행간 34·자간 -0.3을 사용해 존재감을 높입니다. 대표 금액의 크기 36과 나머지 화면의 글자 크기·행간·굵기는 유지합니다.

- `assets/fonts/`: 필요한 정적 글꼴과 각 글꼴의 SIL Open Font License 원문. Pretendard는 공식 v1.3.9 배포본에서 가져왔습니다. 이전 로고 비교용 Quicksand 원본은 보관하되 앱 시작 시 불러오지는 않습니다.
- `src/components/typography.tsx`: 공통 `AppText`·`AppTextInput`과 굵기별 글꼴 매핑. 새 텍스트·입력 UI에도 이 컴포넌트를 사용합니다. 별도의 `fontFamily` 지정은 브랜드처럼 필요한 경우에만 사용합니다.
- 기존 `expo-font`로 앱 시작 시 로컬 파일을 불러옵니다. 추가 글꼴 라이브러리나 네트워크 연결 없이 동작하며, 로딩 오류가 발생해도 기본 글꼴로 앱을 사용할 수 있습니다. 아이콘 폰트와 운영체제에서 표시하는 기본 알림·키보드는 그대로 유지됩니다.

## 공통 관리 버튼

- 상세 화면의 관리 동작은 `ButtonGroup`으로 가로 배치합니다. 주요 동작을 오른쪽에 두어 진행 중 고정비는 삭제·종료·수정, 종료된 고정비는 삭제·재구독/다시 등록, 결제수단은 삭제·수정 순서로 표시합니다. 삭제 확인창은 최종 실행 동작인 삭제가 오른쪽에 오는 기존 구성을 유지합니다.
- 변동 금액 입력은 항목명과 날짜를 간격 2의 정보 묶음으로 표시합니다. 날짜는 공통 설명 스타일의 추가 위 여백을 제거하고 작은 보조 글자로 이름 바로 아래에 붙입니다. ‘실제 금액’ 라벨·입력칸·원 단위는 같은 행에 표시하고 도움말과 오류는 공통 입력칸 바로 아래에서 표시합니다. 입력된 금액이 있으면 ‘미입력으로 변경 → 저장’을 공통 버튼 그룹으로 가로 배치하고, 미입력 상태에서는 저장 버튼만 표시합니다. 공통 버튼 모양으로 보조 동작은 연한 회색 배경·회색 글자, 저장은 연한 파란 배경·파란 글자로 표시합니다. 두 버튼의 높이·둥근 모서리·간격은 같게 유지합니다. 저장 중에는 입력과 두 동작을 비활성화합니다.
- 고정비 상세·변동 금액 입력·총급여 입력·고정비 종료·연말정산 카드 선택은 셀렉트 선택창과 같은 중앙 카드형 팝업으로 표시합니다. 카드 혜택 정산도 변동 카드가 하나 이하이면 팝업, 여러 개이면 전체 화면으로 표시합니다. 사방 여백과 둥근 모서리, 어두운 배경으로 경계를 구분하고 카드 높이는 내용에 맞춥니다. 바깥 영역·닫기 버튼·뒤로 가기로 닫고, 내용이 화면보다 길면 내부에서 스크롤합니다. 상하좌우 안전 영역을 확보하고 키보드가 열리면 팝업의 사용 가능한 공간을 조정하며 저장 중에는 닫기를 막습니다. 여러 항목을 다루는 고정비 등록·수정·재등록, 결제수단 등록·수정과 연결 내역이 있는 상세, 월별 연말정산 사용금액 입력, 긴 소득공제 안내는 전체 화면을 유지하며, 상세에서 입력으로 전환할 때는 같은 네이티브 모달 안에서 내용을 전환합니다.
- 고정비 상세는 이름·금액·결제일, 분류와 유형·결제수단·적용 기간을 한 카드에 묶습니다. ‘생활 · 고정’ 등 분류와 유형은 결제수단 위의 ‘분류’ 행에 표시하고, 결제수단 로고는 기관명·별명 바로 앞에 간격 6으로 붙여 오른쪽에 함께 정렬합니다. 카드 아래 관리 줄은 공통 `ButtonGroup`으로 표시하며 수정·재등록은 연한 파란 배경·파란 글자, 종료는 연한 회색 배경·회색 글자, 삭제는 연한 빨간 배경·빨간 글자로 구분합니다. 금액만 큰 파란 글자로 강조하고 세부 정보는 왼쪽 회색 라벨·오른쪽 값으로 표시합니다. 종료 월과 변동 금액 안내, 결제수단 전체 이름은 보존합니다.
- 모든 실행 버튼은 하나의 공통 디자인을 사용합니다. 주요 동작은 연한 파란 배경·파란 글자, 보조 동작은 연한 회색 배경·회색 글자, 위험 동작은 연한 빨간 배경·빨간 글자로 표시합니다. 버튼 높이는 최소 46, 모서리는 13, 그룹 간격은 8로 둡니다. 탭·필터·선택 목록·아이콘 이동과 상단의 작은 공통 액션은 각 역할에 맞는 컴포넌트를 유지합니다.
- 화면 너비와 글자 배율에 따라 공간이 부족하면 줄바꿈합니다. 기존 삭제 확인, 화면 이동, 저장 중 비활성 처리를 유지하며 등록·저장 등 단일 주요 동작은 기존 전체 너비 버튼을 사용합니다.

## 공통 입력칸

- 텍스트·금액·월 선택을 포함한 폼은 라벨과 입력·선택칸을 같은 행에 두는 것을 기본으로 합니다. 공통 `Field`·`FormSelect`는 가로 배치가 기본이며, 월·결제일·유형 선택도 같은 라벨 폭 96을 사용합니다. 좁은 화면이나 큰 글자에서는 줄바꿈하고, 금액의 원 단위는 입력칸 옆에 표시합니다. 도움말·오류는 해당 입력칸 바로 아래에 표시합니다.
- 직접 입력하는 한 줄 텍스트·금액·검색·결제일은 `AppTextInput`의 공통 지우기 버튼을 기본 사용합니다. 값이 있을 때만 오른쪽에 기존 회색 `close-circle` 아이콘을 표시하고, 빈 값·비활성·읽기 전용 상태에서는 숨깁니다. 입력한 0도 지울 수 있습니다.
- ×를 누르면 기존 `onChangeText`에 빈 문자열을 전달하고 해당 입력칸으로 포커스를 돌립니다. 저장·제출·화면 닫기를 실행하지 않으며, 입력값의 기존 검증·금액 표시·저장 버튼 흐름을 유지합니다. 화면별 지우기 로직을 따로 만들지 않습니다.
- 입력칸에는 지우기 버튼 자리를 미리 확보해 글자와 아이콘이 겹치지 않게 합니다. 지우기 버튼의 터치 너비 44는 유지하고 아이콘만 입력값 쪽으로 4 옮겨, 오른쪽 정렬 값과 아이콘 사이의 보이는 간격을 약 9로 맞춥니다. 결제일 칸의 폭도 공통 버튼과 ‘일’ 단위가 들어가도록 조정합니다. 검색·결제일처럼 가로 배치의 너비는 `containerStyle`로 지정하며 `style`은 기존 입력 테두리·글꼴·안쪽 여백에 사용합니다.
- 네이티브 입력 참조를 그대로 전달해 기존 오류 항목 포커스·스크롤 이동을 유지합니다. iOS 자체 지우기 버튼은 중복 표시하지 않습니다. 여러 줄 입력은 기본 제외하며, 필요한 특수 입력만 `clearable={false}`로 끌 수 있습니다. 선택 상자의 선택값 해제에는 적용하지 않고 선택창 안의 검색어 입력에는 적용합니다.
- 공통 색상 값은 `src/components/theme.ts`에서 관리하고 기존 `ui.tsx`의 `colors` 내보내기도 유지합니다.

## 아이폰에서 실행하기

프로젝트 폴더에서 실행합니다. 이미 실행 중인 Expo 터미널은 Ctrl+C로 종료하고 다시 시작해 주세요.

```sh
npx expo start --go --clear
```

아이폰과 컴퓨터를 같은 Wi-Fi에 연결한 뒤 카메라로 QR 코드를 스캔하고 Expo Go로 엽니다.

1. **결제수단**에서 통장 또는 카드를 등록합니다.
2. **고정비**에서 이름, 고정·변동 유형, 결제일과 결제수단을 입력합니다. 고정 유형만 월 금액을 입력합니다.
3. **홈**에서 월 합계와 다가오는 결제 일정을 확인합니다.

항목을 누르면 상세 정보를 볼 수 있고 수정할 수 있습니다. 고정비는 마지막 반영 월을 선택해 종료하고, 결제수단은 삭제할 수 있습니다. 처음 실행하면 빈 목록으로 시작합니다.

## IntelliJ에서 실행하기

`Run → Edit Configurations → + → npm`에서 실행 설정을 추가합니다. 기존 `start` 스크립트를 사용하므로 별도 실행 스크립트를 추가할 필요는 없습니다.

| 설정            | 값                             |
| --------------- | ------------------------------ |
| Name            | `MonthPin Expo Go`             |
| package.json    | 프로젝트 루트의 `package.json` |
| Command         | `run-script`                   |
| Scripts         | `start`                        |
| Arguments       | `-- --go --clear`              |
| Node runtime    | 설치된 Node.js 22.13 이상      |
| Package manager | `npm`                          |

설정을 저장한 뒤 ▶ 버튼으로 실행합니다. 재실행할 때는 ■ 버튼으로 종료한 뒤 ▶ 버튼을 누릅니다. 실행 중인 다른 개발 서버가 있다면 먼저 종료해 주세요. 아이폰에서는 같은 Wi-Fi에 연결하고 Expo Go로 QR 코드를 스캔합니다. 이 설정은 컴퓨터의 개발 서버 실행을 위한 것이며, 앱의 기존 저장 데이터는 유지됩니다.

## 현재 구현 범위

- 홈 / 고정비 / 결제수단 / 결산 / 설정 하단 탭
- 홈은 영역 사이 간격 16, 다가오는 결제 제목·목록 사이 간격 8을 사용합니다. 합계 카드 안쪽 여백은 20·요소 간격은 10, 결제 목록 카드 안쪽 여백은 16으로 정리하고 하단 일정 설명의 위쪽 여백은 중복하지 않습니다. 합계 금액은 화면 폭·글자 배율·숫자 길이를 고려해 한 줄에 맞추며 날짜·로고·이름·금액의 기본 한 줄 배치를 유지합니다. 홈의 결제 행은 화면 폭을 글자 배율로 나눈 값이 300보다 작을 때만 이름을 두 줄까지 허용하고 금액을 다음 줄 오른쪽에 배치합니다. 날짜 열은 글자 배율에 맞춰 넓히고 전체 보기 버튼의 터치 높이는 44 이상을 유지합니다.
- 결산의 고정비 탭: 연도 이동, 1~12월 지출·카드 혜택과 연간 합계, 혜택 반영 예상액 표시. 연말정산은 연도별 총급여 입력·수정과 총급여의 25% 목표금액 표시
- 고정비 제목 옆 아이콘으로 목록 / 캘린더 전환. 분류 탭은 목록에서 전체·생활·구독만 제공하고 보기 전환용 탭 줄은 추가하지 않습니다. 분류·정렬·상태와 선택 월·날짜를 보기 전환 후에도 유지합니다.
- 목록의 진행 중 / 종료 상태 선택, 진행 중 항목의 수정·종료·삭제, 종료 항목의 재구독(생활 항목은 다시 등록)·삭제
- 고정비 등록·수정·종료와 선택적인 결제수단 연결
- 고정·변동 금액 유형 선택: 고정은 월 금액 필수, 변동은 기본 금액 없이 등록
- 고정비 화면의 전체·생활·구독 탭: 선택한 분류의 목록·개수·고정 합계 표시
- 고정비·결제수단 화면은 동일한 가로 탭, 개수·고정 합계 요약, 오른쪽 순서 변경 버튼, 상단·하단 여백 사용; 결제수단은 통장·카드 탭으로 표시하고 통장 합계에 연결 카드의 고정비 포함
- 두 화면 상단의 `+ 등록` 버튼은 연한 파란 배경·진한 파란 글자의 높이 32 버튼으로 통일하며 테두리 없이 터치 영역은 최소 44 유지
- 고정비 목록·홈의 다가오는 결제·결제수단의 연결 고정비는 공통 행을 사용해 날짜·기관 로고·항목명·금액을 한 줄에 표시하고 은행·카드사명은 생략합니다. 로고는 항목명 바로 앞에 간격 4로 붙이고 금액은 오른쪽 끝에 정렬하며, 공통 한 줄 행은 최소 높이 44·위아래 여백 4를 사용합니다. 홈의 다가오는 결제와 결제수단의 연결 고정비는 목록을 한 그룹으로 묶어 행 사이의 카드 간격 10이 중복되지 않게 합니다. 제목·안내문과 목록 사이의 카드 간격은 유지하며 종료 월·미지정 안내가 있는 두 줄 항목은 최소 높이 52를 사용합니다. 별도의 높이 옵션 없이 공통 행에서 같은 기준을 적용합니다. 종료 적용 월과 결제수단 미지정 안내는 별도 보조 줄로 보존합니다. 변동 항목은 금액 대신 ‘변동’을 표시합니다.
- 결제수단 종류 접두어는 생략하고 종료 월·미지정 안내는 같은 회색·보통 굵기의 보조 줄로 표시합니다. 로고는 배경·테두리 없이 비율을 유지해 실제 크기 15로 표시합니다. 이전 배치 비교용 분기는 제거하고 공통 행의 이름 앞 로고 구성을 모든 사용처와 순서 변경에 적용합니다. 캘린더의 날짜별 내역도 같은 크기·간격의 로고를 이름 앞에 표시하며 기관명·통장·카드 접두어를 별도 줄에 반복하지 않습니다. 이름과 금액을 한 줄에 맞추며, 수정 가능·자동 반영 문구와 상태 아이콘은 별도 줄로 표시하지 않습니다.
- 고정비의 합계·정렬 버튼 간격과 정렬 버튼·목록 간격은 각각 4로 줄이고, 정렬·순서 변경 버튼은 오른쪽에 함께 배치; 버튼 터치 영역은 최소 44 유지
- 결제일은 연한 회색 배경과 진한 회색 글자의 작은 뱃지(34×24)에 `05일` 형식으로 표시; 모서리만 둥글게 하고 테두리·그림자 없이 구성; 고정비 목록·순서 변경·결제수단의 연결 고정비에 동일하게 적용하며 홈의 다가오는 결제는 월/일 표시 유지
- 고정 월 금액 입력 시 천 단위 쉼표 자동 표시 (추가·수정 모두 적용), DB에는 숫자로 저장
- 고정비의 결제수단 선택 목록은 통장 다음 카드 순서이며, 각 종류 안에서는 저장한 드래그 순서 유지
- 고정비 목록의 기본 정렬은 결제일이 빠른 순서이며 같은 결제일은 금액이 큰 순서, 금액도 같으면 먼저 등록한 항목부터 표시; 금액 없는 변동 항목은 같은 결제일의 고정 금액 항목 아래에 표시; 정렬 메뉴에서 결제일순·등록순·금액순·내 순서 선택
- 정렬은 버튼 아래에 겹쳐 뜨는 팝오버 메뉴로 표시; 선택 항목에 체크 표시, 선택·바깥 터치·뒤로 가기로 닫기, 항목이 많으면 메뉴 안에서 스크롤
- 정렬 버튼은 기본 글자 크기에서 높이 32, 터치 영역은 최소 44로 유지; 팝오버 폭은 최대 176, 항목의 터치 높이는 최소 44
- 두 화면 오른쪽에 정렬 필터·순서 변경 아이콘을 차례로 붙여 표시; ‘순서 변경’은 회색 위아래 화살표이며 접근성 이름과 최소 44 터치 영역 유지; 드래그 편집 중에는 안내 문구와 오른쪽 ‘완료’만 표시
- 두 목록은 평소 일반 FlatList를 사용하고 순서 변경 중에만 드래그 목록 사용; 모드 전환 시 스크롤 위치를 이어받으며 다른 화면으로 이동하면 임시 편집·드래그 상태 종료
- 결제수단 정렬은 기관순(기본)·등록순·고정비순·내순서 제공; 기관순은 같은 은행·카드사끼리 모은 뒤 별명순, 등록순은 먼저 등록한 항목부터, 고정비순은 연결된 고정 금액 합계가 큰 순서
- 금액순은 금액 내림차순, 같은 금액은 이름 가나다순으로 표시; 금액이 없는 변동 항목은 아래에 가나다순으로 표시
- 고정비의 ‘순서 변경’에서 오른쪽 손잡이를 드래그해 이동하고, 놓으면 직접 정한 순서 저장
- 은행·통장 별명, 카드사·카드 이름, 카드 대금 출금 통장·출금일
- 통장·카드 등록 및 수정 시 주요 은행 10곳·카드사 9곳 선택 목록과 기관별 로고 이미지
- 금융기관 로고는 `assets/providers/`에 앱과 함께 저장해 오프라인에서도 표시; `src/data/provider-logos.ts`에서 기존 기관 코드와 연결하고, 이미지 출처는 `assets/providers/README.md`에 기록
- 카드 등록·수정 시 카드사·카드 이름·신용/체크 종류·연결 통장·월 혜택 유형·금액은 모두 필수이며, 신용카드는 대금 출금일도 필수; 체크카드는 출금일 입력·저장·목록·상세 표시 제외
- 결제수단 등록의 통장·카드와 등록·수정의 신용·체크 선택은 고정비와 같은 제목 옆 선택 버튼으로 통일; 은행·카드사와 출금·연결 통장은 동일한 높이 44의 검색형 셀렉트 사용; 신용카드 출금일은 결제일과 같은 짧은 숫자 입력칸으로 1~31일을 입력하며 빈 값은 허용하지 않음
- 결제수단 목록의 ‘순서 변경’에서 오른쪽 손잡이를 드래그해 이동, 통장·카드별 순서 저장
- 이름·기관·월 고정비 중심의 간결한 목록, 카드의 출금 정보를 한 줄로 표시
- 카드 대금을 내는 통장 기준의 고정 금액 합계와 중복 없는 전체 고정 금액 합계 (변동 항목 제외)

- 고정비 캘린더: 월 이동·오늘 이동, 날짜별 합계 캘린더, 선택 날짜의 내역과 월 합계
- 고정 금액 자동 반영, 변동 항목의 월별 실제 금액 입력·수정·미입력으로 되돌리기 (0원 입력 가능)
- 고정비 추가는 시작 월, 금액·유형 수정은 적용 월, 종료는 마지막 반영 월 선택 (기본 이번 달): 이전 달과 직접 입력한 실제 금액 보존
- 고정비 등록·수정의 분류·금액 유형은 제목 옆의 간결한 선택 버튼으로 제공; 결제일은 숫자 입력칸과 `일` 표시로 구성하고 입력 중 1~31일 범위를 바로 검증; 결제수단은 같은 줄의 간결한 셀렉트로 제공하며 통장 → 카드로 그룹화해 별명·기관명 검색·선택
- SQLite 기기 저장: 앱 재시작 후에도 유지

서버, 계정 로그인, 자동 금융 연동, 알림, 기기 간 자동 동기화는 구현하지 않았습니다. 앱 삭제나 앱 데이터 초기화 시 데이터가 사라질 수 있습니다. Expo Go에서 저장한 데이터는 해당 개발 프로젝트의 데이터이며, 웹이나 스토어 앱으로 자동 이전되지는 않습니다.

### Expo Go 데이터 백업과 웹 이전

- 설정의 **백업 내보내기**로 몬스핀 DB의 모든 기록을 JSON 파일로 저장합니다. 결제수단·고정비·월별 기록·금액 변경 이력·카드 혜택 설정/확정 내역·연말정산·이자 수입과 삭제한 항목의 이력을 포함합니다. ID·참조·정렬·자동 증가 번호도 보존합니다. 다른 앱의 데이터는 읽지 않습니다.
- 휴대폰에서 파일 앱 등 본인만 접근할 수 있는 위치에 저장한 뒤, 배포된 웹의 설정에서 **백업 불러오기**를 선택합니다. 백업 날짜와 건수를 확인하고 불러오기를 누릅니다. 원래 Expo Go 데이터는 그대로 유지됩니다.
- 기존 기록을 덮어쓰거나 합치지 않습니다. 초기 금융기관 목록 외에 기록이 하나라도 있는 앱에서는 복원을 거부합니다. 같은 DB 버전의 백업만 지원하며, 파일 구조·DB 제약·참조를 검증하고 트랜잭션 실패 시 전체 복원을 되돌립니다. 파일 크기는 20MB까지 지원합니다.
- 백업 파일에는 연봉·금액 등 개인 정보가 포함되며 암호화되지 않습니다. 저장소나 `public/`, `dist/`에 넣거나 호스팅에 업로드하지 않습니다. 호스팅에는 앱 코드와 정적 에셋만 배포합니다.
- 이전 후 각 기기/브라우저/주소의 데이터는 독립적으로 저장됩니다. 앞으로 웹을 주로 사용하고, 브라우저 데이터 삭제 전이나 기기 변경 전에는 다시 백업합니다. 백업 내보내기 후 실제 파일 저장 여부는 선택한 저장 위치에서 확인해야 합니다.

### Cloudflare Pages 웹 배포

`npm run build:web`으로 `dist/`를 생성합니다. `web.output`은 클라이언트 렌더링을 사용하는 `single`입니다. SQLite 웹 실행에 필요한 WASM 확장자는 `metro.config.js`, 배포 응답의 COOP/COEP 헤더는 `public/_headers`에서 설정합니다. Metro를 재시작하면 로컬 웹에도 같은 헤더를 적용합니다.

Cloudflare Pages는 `node_modules` 폴더를 정적 에셋에서도 제외합니다. 빌드 마지막의 `scripts/prepare-pages.cjs`가 Expo의 의존성 에셋을 `dist/assets/vendor/`로 옮기고, `public/_redirects`의 내부 재작성 규칙으로 기존 번들 URL을 연결합니다. SQLite WASM과 아이콘 폰트를 함께 보존하며, WASM 파일이 없거나 경로 규칙이 빠지면 빌드를 실패시킵니다. 앱 DB나 네이티브 앱의 에셋 경로는 변경하지 않습니다.

운영 주소는 `https://month-pin.pages.dev`입니다. GitHub Actions에서 검사·빌드를 통과한 `dist/`만 기존 Cloudflare Pages 프로젝트 `month-pin`에 업로드합니다. Cloudflare의 Git 연결은 유지하되 Branch control에서 자동 운영 배포를 끄고 Preview branch를 None으로 설정해 중복 검사·빌드를 방지합니다. 프로젝트를 새로 만들거나 운영 주소를 바꾸지 않습니다.

로컬에서 전체 검증과 배포 파일 생성을 함께 실행하려면 `npm run build:deploy`를 사용합니다. 이 명령은 린트 → 타입 검사 → 테스트 → 웹 빌드를 순서대로 실행하고 실패 시 중단합니다. 실제 데이터는 매번 바뀌는 미리보기 주소 대신 고정된 운영 주소에서 불러옵니다.

배포 후 HTTPS, COOP/COEP, SQLite 로딩·저장·새로고침 후 유지와 백업 복원을 확인합니다. 웹 SQLite는 Expo에서 알파 지원으로 안내하고 있으므로 실제 휴대폰 브라우저에서도 확인합니다. 웹 배포는 기기 간 동기화나 서버 DB 연결을 추가하지 않습니다.

### GitHub 자동 검사와 배포

`.github/workflows/ci.yml`의 `CI` 워크플로가 모든 브랜치 푸시와 PR, 수동 실행에서 작동합니다. 잠금 파일 기준으로 의존성을 설치한 뒤 `npm run check`와 `npm run build:web`을 한 번 실행하며, 결과는 GitHub 저장소의 Actions 탭과 커밋의 체크에서 확인합니다. 같은 브랜치에 새 푸시가 오면 이전 실행을 취소합니다. 검사와 배포는 `.node-version`의 Node.js 22 계열을 사용합니다.

`master` 푸시 또는 `master`에서의 수동 실행이 성공하면 `web-dist` 아티팩트를 저장하고, `needs: check-and-build`로 연결된 별도 배포 작업이 해당 실행의 파일을 내려받아 공식 Wrangler로 배포합니다. 아티팩트는 1일 보관하며 앱 코드와 정적 에셋만 포함합니다. PR과 다른 브랜치는 배포하지 않습니다. 검사·빌드가 실패하거나 취소되면 배포 작업이 시작되지 않고 기존 사이트가 유지됩니다.

GitHub 저장소 Settings → Environments의 `production` 환경에는 배포 가능 브랜치를 `master`로 제한하고 다음 값을 등록합니다.

- 환경 Secret `CLOUDFLARE_API_TOKEN`: 해당 Cloudflare 계정의 Cloudflare Pages Edit 권한만 가진 배포 토큰. 토큰 원문은 Git이나 문서·로그에 남기지 않습니다. 이 권한은 프로젝트 하나가 아닌 선택한 계정의 Pages에 적용됩니다.
- 환경 Variable `CLOUDFLARE_ACCOUNT_ID`: Cloudflare 계정 ID. 비밀번호가 아니므로 일반 환경 변수로 관리합니다.

토큰은 배포 작업에만 전달하며 의존성 설치·테스트·앱 빌드에는 주입하지 않습니다. Actions와 Wrangler는 확인한 버전으로 고정합니다. 앱의 화면·저장 데이터·백업 파일은 이 설정 변경의 영향을 받지 않습니다. 기존 Git 연동 프로젝트에도 자동 배포를 끈 뒤 Wrangler로 배포할 수 있습니다. [Cloudflare 공식 안내](https://developers.cloudflare.com/pages/configuration/git-integration/#disable-automatic-deployments)

은행·카드사 목록은 `src/data/providers.ts`에서 관리합니다. `bank_kb`, `card_samsung` 같은 앱 내부 고정 코드는 공식 금융기관 코드와 별개이며, 기관 이름을 변경해도 코드는 유지해야 합니다. DB에는 기관 목록을 `payment_providers`로 관리하고, 결제수단은 `providerCode`로 참조합니다. 새 등록과 수정은 목록 선택만 허용합니다.

DB 버전 1의 기존 기관명은 버전 2로 자동 이전합니다. 알려진 이름·약칭은 기관 코드로 연결하고, 매칭되지 않는 이름은 기존 기록과 연결을 보존하기 위해 `legacyProvider`에 남깁니다. 해당 기록을 수정할 때는 지원하는 기관을 선택해야 합니다. 이전 과정은 트랜잭션으로 처리하며 고정비·출금 통장 연결과 기존 ID를 유지합니다.

DB 버전 3에서는 결제수단에 `sortOrder`를 추가합니다. 기존 통장·카드별 직접 정한 순서는 유지하고, 새 항목은 내순서와 등록순에서 맨 아래에 추가합니다. ‘순서 변경’을 누르면 내순서로 전환하며 오른쪽 손잡이를 잡고 이동하면 항목이 살짝 확대되고, 화면 가장자리에서는 목록이 자동으로 스크롤됩니다. 놓으면 즉시 저장되며 ‘완료’는 편집 모드를 종료합니다. 저장에 실패하면 이전 순서로 돌아갑니다. 직접 정한 순서는 이름 수정·다른 탭 전환·앱 재시작 후에도 유지됩니다.

결제수단 정렬 코드는 `src/data/method-types.ts`의 `provider` / `registered` / `amount` / `custom`으로 관리합니다. 기본 기관순은 기관 이름의 가나다순이며 KB국민·NH농협·IBK기업·SC제일·BC카드는 한글 기관명 기준으로 정렬합니다. 같은 기관 안에서는 별명순, 별명도 같으면 고유 ID 순서입니다. 고정비순은 통장에 연결된 카드의 고정비도 합산하며 금액 없는 변동 항목은 제외하고, 합계가 같으면 기관·별명순으로 표시합니다. 정렬 선택은 두 탭에 공통 적용하며 앱 재시작 시 기관순으로 표시합니다. 필터를 바꾸어도 저장된 내순서는 유지됩니다.

카드 탭은 체크카드 → 신용카드 두 구역으로 나누고 제목에 개수를 표시합니다. 구역 사이에는 여백을 추가하고, 카드가 없는 구역과 종류 미지정 구역은 표시하지 않습니다. 종류가 누락된 기존 카드는 임의로 분류하거나 삭제하지 않으며, 해당 카드가 있을 때만 ‘카드 정보 확인’ 안내에서 상세·수정·삭제에 접근할 수 있습니다. 전체 카드 개수와 합계에는 이 기록도 포함합니다. 일반 조회 중에는 카드 행에 드래그 제스처를 붙이지 않고 화면 전체에서 하나의 스크롤을 사용합니다. 드래그 목록은 순서 변경 중에만 표시합니다. 카드 등록·수정의 종류 선택, 고정비의 결제수단 선택, 통장의 연결 카드, 카드 혜택 정산, 연말정산 카드 선택·입력도 체크카드 → 신용카드 순서로 맞춥니다. 종류를 확인할 수 없는 기존·삭제 카드의 저장 금액은 유지하며 종류가 확인되는 카드 뒤에 표시합니다. 선택한 정렬은 각 구역 내부에 적용하고 구역 순서는 유지합니다. ‘내순서’의 드래그와 접근성 이동도 같은 종류 안에서만 허용하며, 저장 시 누락 카드의 기존 순서 자리와 참조를 보존합니다. 카드 종류를 수정하면 해당 구역으로 이동합니다. 통장 목록의 정렬·순서 변경은 기존 기준을 유지합니다.

DB 버전 4에서는 고정비에 `amountTypeCode`를 추가하고 `fixed` / `variable` 코드로 유형을 관리합니다. 공통 목록은 `src/data/expense-types.ts`에 정의합니다. 고정 항목은 월 금액이 필수이며, 변동 항목은 금액을 `NULL`로 저장합니다. 앱 저장 계층과 DB 제약 조건에서 유형·금액 조합을 검증합니다. 기존 항목은 금액·ID·결제일·결제수단 연결을 보존한 채 고정 유형으로 자동 이전됩니다. 수정 화면에서 변동 유형으로 바꾸면 기존 기본 금액은 제거됩니다.

DB 버전 5에서는 고정비에 `sortOrder`를 추가합니다. 기존 항목의 ID·유형·금액·결제수단 연결은 유지하고, ‘내 순서’의 초기값은 먼저 등록한 항목부터 설정합니다. 새 항목은 등록순과 내 순서에서 맨 아래에 추가되고, 결제일순에서는 해당 결제일·금액 위치에 표시됩니다. 정렬 코드는 `src/data/expense-types.ts`의 `charge_day` / `registered` / `amount` / `custom`으로 관리합니다. ‘순서 변경’은 내 순서로 전환하며 드래그 후 즉시 저장합니다. 다른 정렬로 보더라도 저장한 순서는 유지되며, 앱 재시작 시 기본 결제일순으로 표시하고 ‘내 순서’를 선택하면 저장된 순서로 볼 수 있습니다. 결제일·금액이 모두 같은 항목, 등록순과 금액·이름이 모두 같은 항목의 순서는 고유 ID로 결정하므로 중복된 이름도 구분됩니다.

DB 버전 6에서는 고정비에 `categoryCode`를 추가합니다. 분류는 `src/data/expense-types.ts`의 `living` / `subscription` 코드로 관리하며 금액 유형과 별개입니다. 기존 항목은 분류를 임의로 추정하지 않고 `NULL`로 이전해 ‘전체’ 탭에 유지합니다. 등록·수정 화면에서 생활·구독을 선택하며, 특정 분류 탭에서 추가하면 해당 분류가 미리 선택됩니다. 상세 화면에서는 분류·금액 유형·결제수단 별명을 확인할 수 있습니다. 분류 탭 안에서 순서를 변경할 때는 전체 저장 순서 중 해당 항목의 자리만 재배치해 다른 분류와 미분류 항목의 순서를 보존합니다. 분류를 바꿔도 금액·연결·저장한 순서는 유지됩니다.

DB 버전 7에서는 결제수단에 `cardTypeCode`를 추가합니다. 카드 종류는 `src/data/method-types.ts`의 `credit` / `debit` 코드로 관리하고 통장은 `NULL`을 저장합니다. 기존 카드는 종류를 이름·출금일로 추정하지 않고 `NULL`로 이전하며 종류 미지정으로 표시합니다. 수정 시 신용카드·체크카드를 선택해야 합니다. 체크카드는 출금일을 저장하지 않으며 신용에서 체크로 바꾸면 저장 시 기존 출금일이 제거됩니다. ID·이름·연결 통장·고정비 참조·내순서는 유지됩니다.

DB 버전 8에서는 `ledger_entries`에 월별 가계부 내역을 별도로 저장합니다. 고정비·결제수단의 기존 데이터와 ID·참조·정렬은 유지합니다. 월을 열 때 그 시점의 고정비 목록에서 반영 기간에 해당하고 아직 없는 내역을 만들며, 고정 항목은 등록 금액을 채우고 변동 항목은 금액을 `NULL`로 시작합니다. 금액 미입력은 합계에서 제외하며 0원은 입력 완료로 구분합니다. 동일 이름의 고정비도 `expenseId`로 구분하고, 같은 월·같은 항목을 중복 생성하지 않습니다. 29~31일이 없는 달은 마지막 날로 조정합니다.

월 내역에는 이름·분류·결제일·금액·기관 코드와 표시명·결제수단 별명·카드 종류를 함께 보존합니다. 이름·분류·결제일·결제수단의 수정은 이미 만들어진 월 내역을 덮어쓰지 않습니다. 금액·유형 변경은 아래 적용 월 규칙을 따릅니다. 종료한 고정비는 기록을 보존하고 마지막 반영 월까지만 자동 내역을 생성합니다. 새 고정비는 선택한 시작 월 이후라면 이미 열어 본 월에도 다음 조회 시 추가됩니다.

DB 버전 9에서 도입한 금액 이력은 버전 11에서 월 기준으로 통일합니다. 추가 시 ‘시작 월’, 금액·고정/변동 유형 수정 시 ‘변경 적용 월’, 종료 시 ‘마지막 반영 월’을 선택하며 기본값은 모두 이번 달입니다. 월 선택은 연도 이동과 12개월 버튼으로 제공하고 날짜 입력·일별 달력은 제거합니다. 시작 월은 과거 월도 선택할 수 있고 변경·종료는 이전 달 기록을 보호하기 위해 이번 달 이후만 선택합니다. 시작 월의 결제일이 이미 지났어도 그달부터 표시합니다. 종료는 마지막 반영 월까지 포함하며 다음 달부터 자동 내역을 생성하지 않습니다. 종료 버튼을 저장하면 진행 중 목록에서 제외하고 종료 목록으로 옮기며, 원본과 금액 이력을 DB에 남겨 나중에 처음 여는 이전 달에도 기록을 생성할 수 있습니다.

금액·유형 변경은 선택한 월 전체에 적용하며 이전 달과 직접 입력한 실제 금액(0원 포함)은 유지합니다. 선택한 월 이후 미리 생성된 자동 내역도 새 금액으로 갱신합니다. 같은 적용 월 및 그 이후에 예약된 금액은 이번 변경으로 대체합니다. 종료 이후 미리 생성된 자동 내역은 제거하되 직접 입력한 실제 금액은 남깁니다. 종료한 달 이후의 실제 금액을 미입력으로 되돌리면 다음 월 조회에서 제외됩니다. 기존 고정비의 시작 월은 등록 시점을 알 수 없어 기존 표시 범위가 유지되는 `1000-01`로 이전합니다. 기존 날짜 이력은 `effectiveMonth`로 옮기며 같은 달에 여러 변경이 있으면 마지막 날짜의 설정을 유지합니다. 이전에 저장된 월 내역은 데이터 이전에서 덮어쓰지 않습니다.

수정 화면에서도 시작 월을 변경할 수 있습니다. 시작 월을 더 늦은 월로 바꾸면 그보다 이전의 자동 내역만 정리하고 직접 입력한 실제 금액은 0원도 포함해 보존합니다. 시작 월을 더 이른 월로 바꿔 기간을 늘리면 월 조회 시 기존 금액 이력에 맞춰 빠진 내역을 생성하며, 같은 월·항목은 중복되지 않습니다. 원본 ID·결제수단 연결·정렬·금액 이력은 유지하고 시작 월·금액 변경·자동 내역 정리는 같은 트랜잭션으로 저장합니다. 예전 항목의 `1000-01`은 화면에 ‘기존 전체 기간’으로 표시하고 월 선택을 열면 올해를 보여줍니다. 실제 월을 선택하지 않고 이름·금액만 수정하면 기존 시작 범위를 그대로 유지합니다. 시작 월 이전에 보존된 실제 금액을 미입력으로 되돌리면 다음 조회에서 제외됩니다.

월 내역의 `amountEntered`는 직접 입력 여부를 나타내는 boolean flag이며 DB에는 `0/1`로 저장합니다. 버전 8에서 입력한 변동 금액은 0원도 입력 완료로 이전합니다. 금액 변경 이력·고정비 수정·미래 내역 갱신은 하나의 트랜잭션으로 처리해 실패 시 모두 되돌립니다. 이전 버전 데이터는 현재 등록 금액을 최초 기준값으로 보존하고 기존 월 기록을 변경하지 않습니다. 이후 처음 여는 과거 월에도 보존된 금액 이력을 적용합니다. 다만 이전 버전에서 이미 사라진 가격 변경 이력이나 실제 승인·청구 기록을 복원하지는 않습니다.

고정비 캘린더의 월 합계는 자동 반영한 고정 금액과 직접 입력한 변동 금액을 더합니다. 홈도 같은 월별 내역 조회와 합계 계산을 사용하며 ‘10월 고정비 합계’처럼 현재 월을 명시합니다. 시작·종료 월과 해당 월의 금액 이력을 반영하고 미입력 금액은 합계에서 제외해 별도로 표시합니다. 0원은 입력 완료로 구분합니다. 홈에서 앱이 다시 활성화되거나 자정이 지나면 현재 날짜와 월을 갱신합니다. 고정비 목록·결제수단의 합계는 등록한 고정 금액만 포함하는 설정 요약입니다. 캘린더는 반복 항목의 월별 금액 기록을 제공하며 일반 지출의 자유 등록, 실제 승인·출금 확인, 연도별 연말정산 집계·공제 계산은 제공하지 않습니다. 추후 연말정산 확장에 사용할 수 있도록 월 내역 생성 당시의 카드 종류를 보존합니다.

캘린더의 날짜별 내역도 다른 고정비 목록처럼 `로고 + 고정비명 | 금액` 한 줄로 표시합니다. 로고와 이름 간격은 4, 행 높이는 최소 44, 상하 여백은 4로 맞춥니다. 기관명은 반복하지 않고 결제수단 미지정일 때만 최소 높이 52의 보조 줄로 안내합니다. 날짜·일 합계 줄과 카드 내부는 같은 좌우 여백 12를 사용하며 날짜는 15 크기, 일 합계는 회색 14 크기로 표시합니다. 변동 금액은 파란색, 고정 금액은 기본 글자색으로 구분하고, 미입력은 ‘금액 입력’으로 표시합니다. 수정 가능·자동 반영 문구와 상태 아이콘은 화면에서 제거하되 접근성 안내에는 유지하며 변동 항목만 행 전체를 눌러 금액을 입력·수정할 수 있습니다.

캘린더와 홈의 월별 조회는 데이터 갱신 번호로 결과를 구분합니다. 저장·수정·종료·삭제·실제 금액 입력 후 다시 조회하며 목록을 재조회하지 못한 경우에도 이전 월 화면 값을 재사용하지 않습니다. 저장 중이거나 월·갱신 번호·재시도 요청이 달라지면 이전 결과는 숨기고 새 조회 결과만 표시합니다. 화면 전환이나 월 이동 후 늦게 도착한 이전 요청은 무시합니다. 이 갱신 번호는 화면 상태이며 DB 스키마 버전과 별개입니다.

하단 메뉴는 홈 → 고정비 → 결제수단 → 결산 → 설정 순서입니다. 기존 가계부는 고정비의 캘린더 보기로 합칩니다. 제목 옆 아이콘으로 목록과 캘린더를 전환하고, 두 보기의 선택 상태를 유지합니다. 캘린더는 보이는 동안에만 월 내역을 불러옵니다. 월 이동·재조회 중에도 합계 카드와 달력·선택 날짜 제목을 유지하고 조회 전 금액은 ‘—’로 표시합니다. 고정비와 카드 혜택 조회가 모두 끝난 뒤 금액·건수·미입력 표시·혜택 확정 상태를 함께 갱신합니다. 조회 중·실패 시 이전 월의 내역과 상태는 숨기며 금액 수정·혜택 정산을 열지 않습니다. 날짜 선택과 월 이동은 유지하고, 오류 안내·재시도는 날짜 제목 아래에 표시합니다. 월별 주 수에 따른 달력 높이 변화는 유지합니다. 앱을 새로 시작하면 캘린더 보기·현재 월·오늘 날짜로 표시합니다. 홈의 ‘전체 보기’로 이동할 때는 직전 보기와 관계없이 고정비 목록을 엽니다. 이동 요청을 적용한 뒤 경로의 보기 지정값을 비워, 이후 일반 탭 이동에서는 사용자가 마지막으로 선택한 목록·캘린더 보기를 유지합니다. 목록의 초기 필터는 진행 중·전체·결제일순이며 앱 사용 중 선택한 보기와 각 보기의 상태를 유지합니다.

### 결산

결산은 기존 결제수단 화면과 같은 가로 탭으로 ‘고정비 → 이자 → 연말정산’을 전환합니다. 처음에는 고정비·올해를 표시하고, 세 보기에서 선택한 연도를 공유합니다. 고정비 탭의 연도 선택은 합계 바로 아래·월별 표 위에 두며 ‘월별 요약’ 제목을 대신합니다. 연말정산도 목표금액 카드 아래·월 격자 위에 배치해 합계 → 연도 선택 → 월별 내역 순서를 맞춥니다. 세 보기 모두 탭 아래 첫 영역까지 여백은 20이며, 연도 선택은 조회 중·오류·빈 상태에서도 사용할 수 있습니다. 다른 연도를 볼 때만 되돌림 아이콘과 현재 연도(예: 2026년)를 담은 보조 버튼을 표시하며, 누르면 현재 연도로 돌아갑니다. 앱 사용 중 선택한 보기와 연도·각 보기의 스크롤 위치를 유지하며, 연말정산에서 연도를 바꾸면 이전 연도의 입력 창과 임시 입력값은 닫고 새 연도 정보를 불러옵니다. 연말정산 화면 자체는 다시 만들지 않고 목표금액 카드와 월 격자를 유지합니다. 조회 중에는 이전 연도의 값 대신 금액과 카드 개수를 대시로 표시하고 입력·카드 선택을 잠시 막으며, 큰 로딩 영역으로 카드를 교체하지 않습니다. 조회 실패 안내와 재시도는 카드 아래에 표시합니다.

이자 탭은 예금·적금에서 받은 이자 수입을 연도별로 관리하며 납입액·잔액·만기 관리는 포함하지 않습니다. 상단 흰색 요약 카드는 제목·금액과 상하 12의 여백만 유지하고 최소 높이를 강제하지 않습니다. 요약 카드 → 공통 연도 선택 → 1~12월 3열 × 4행 격자를 사용하고 격자 스타일은 연말정산과 공유합니다. 상단은 선택 연도에 저장된 모든 행의 합계, 각 월은 해당 월 행의 합계를 표시합니다. 월 격자 아래의 ‘이자 내역’에는 선택한 연도의 전체 내역을 월 오름차순으로 나열하고 같은 월에서는 저장 순서를 유지합니다. 기존 고정비 목록처럼 최소 높이 44의 행에 월 → 금융기관 로고·통장 별명 → 금액을 배치하며, 별명이 비어 있으면 기관명을 표시합니다. 목록을 누르면 해당 월의 입력 창을 열어 수정합니다. 실제 일자는 저장하지 않으므로 날짜 열에는 입력한 월을 표시합니다. 빈 연도의 연간 합계는 0원이며 월별 내역 없음은 ‘-’, 명시적으로 저장한 0원은 ‘0원’으로 구분합니다. 조회 중·실패 시에도 영역을 유지하고 이전 연도의 금액 대신 대시를 표시합니다. 연도·갱신 번호·재시도·화면 활성 상태로 늦은 응답을 차단하며 다른 탭을 보는 동안에는 조회를 중지합니다.

월을 누르면 공통 팝업에서 은행·이자 수입·통장 별명을 입력합니다. 은행은 기존 공통 목록과 로고를 사용하고 `providerCode`로 관리합니다. 은행과 금액은 필수이며 통장 별명은 40자 이내의 선택 입력입니다. 금액은 원 단위 정수 0~9,999,999,999원을 허용하며 새 입력칸은 비워 둡니다. 내역마다 연한 배경의 카드로 묶고, 카드는 상단 빈 줄 없이 은행 입력부터 시작하며 입력 줄 간격은 8입니다. 카드 하단 오른쪽에 공통 작은 버튼으로 ‘내역 삭제’를 두고, 누르는 영역은 최소 44를 유지합니다. 상단 삭제 아이콘·더보기 메뉴는 사용하지 않습니다. 은행·통장 별명·이자 수입은 라벨과 입력칸이 같은 행에 오고 입력칸 시작선이 일치하도록 배치하며, 좁은 화면·큰 글자에서는 줄을 나눕니다. 마지막 카드 아래의 넓은 보조 버튼 ‘+ 이자 내역 추가’는 기존 값을 유지하며 새 카드를 추가합니다. 같은 은행·같은 별명도 서로 다른 행 ID로 구분합니다. 공통 입력 지우기는 해당 입력칸만 비우고 카드 하단의 ‘내역 삭제’는 해당 내역을 제거합니다. 이자 수입의 ‘원’은 입력칸 안에서 지우기 X 왼쪽에 표시하여 통장 별명 입력과 입력칸 너비·지우기 위치를 맞춥니다. 합계는 기본 0원으로 표시하고 유효하게 입력한 금액을 합산합니다. 빈 값이나 잘못된 값은 합계에서 제외하되, 저장 시 필수 입력·금액 검증을 유지합니다. 저장을 눌러야 해당 월에 반영합니다. 모든 행을 삭제하고 저장하면 해당 월 내역을 비웁니다. 닫기·취소는 기존 저장값을 유지하고, 저장 실패 시 입력값을 보존합니다. 저장 중에는 입력·닫기·중복 실행을 막으며 연도·탭이 바뀌면 이전 월의 입력 창을 닫습니다. 많은 행·키보드·안전 영역은 공통 팝업의 내부 스크롤로 대응합니다.

DB 버전 20은 `interest_income_entries`를 추가합니다. 행별 `id`, `year`, `month`, `providerCode`, `accountAlias`, `amount`, `sortOrder`를 저장하고 은행 종류로 제한한 기관 외래키를 적용합니다. 수정은 기존 ID를 유지하며 행 삭제·삽입·정렬 갱신을 해당 월의 한 트랜잭션으로 처리합니다. 다른 월·연도의 ID를 저장하는 요청은 거부하고 월·연간 합계는 조회 결과에서 계산합니다. 신규 설치와 기존 설치에 같은 스키마를 적용하고 이전 실패 시 테이블·인덱스와 버전 변경을 되돌립니다. 기존 고정비·결제수단·카드 혜택·연말정산 데이터는 유지합니다.

고정비 탭은 선택 연도의 1~12월을 고정비 캘린더와 같은 월별 기록·금액 이력 기준으로 불러옵니다. 아직 열지 않은 월도 기존 월별 조회 절차로 필요한 고정비 내역을 만들며, 이 연도 조회는 기존 DB 작업 대기열 안의 한 트랜잭션으로 처리해 중간 실패 시 생성 내역을 되돌립니다. 시작·종료·삭제 반영 기간과 직접 입력한 변동 금액을 유지하고, 미래 월의 예정된 고정 지출도 포함합니다. 변동비 미입력은 합계에서 제외하고 건수를 표시하며, 입력한 0원은 정상 금액으로 반영합니다.

카드 혜택은 각 월의 확정 금액을 우선하고 미확정 월은 해당 월에 적용되는 예상액을 합산합니다. 카드 수정·삭제 이전의 예상액과 확정액 보존 기준도 캘린더와 같습니다. 연간 지출 합계, 카드 혜택, 혜택 반영 예상액(지출 − 혜택)을 표시하며 마지막 금액은 기존 파란색으로 강조합니다. 카드 혜택은 고정비 캘린더와 같이 연간 합계와 월별 표 모두 양수일 때 ‘−’를 붙이고, 0원은 ‘0원’, 내역 없음은 ‘—’로 표시합니다. 저장 금액과 합계 계산은 바꾸지 않습니다. 합계와 연도 선택 사이에는 일반 설명을 두지 않습니다. 금액 미입력 건수와 혜택 미확정 개월 수만 해당 상태가 있을 때 월별 표 아래에 짧게 표시합니다. 월별 표에는 지출·혜택과 미입력·예상 포함 상태를 표시하며, 내역이 없으면 ‘—’, 등록·입력된 0원은 ‘0원’으로 구분합니다. 해당 연도에 지출과 혜택이 모두 없어도 합계 카드·연도 선택·1~12월 표를 유지하며 합계는 0원, 월별 내역 없음은 ‘—’로 표시합니다. 조회 중·실패 시에도 같은 영역을 유지하고 이전 연도의 금액·상태 대신 ‘—’를 표시하며, 오류 안내와 재시도는 합계 아래에 둡니다.

연간 조회도 연도·데이터 갱신 번호·재시도·저장 상태에 따라 이전 결과를 즉시 숨기고 늦은 응답을 무시합니다. 다른 결산 탭을 보는 동안에는 조회를 중지하고, 고정비 탭이나 결산 메뉴로 돌아오면 다시 조회합니다.

연말정산은 선택 연도의 ‘목표금액’을 가장 위에 표시하고, 카드 오른쪽 하단의 ‘연봉 입력/수정’ 주요 버튼에서 기존 등록 폼과 같은 모달을 엽니다. 별도의 총급여 고정 영역은 두지 않으며, 기본 화면의 텍스트와 접근성 설명에는 저장된 총급여 금액을 노출하지 않습니다. 저장된 값은 사용자가 입력·수정 모달을 열었을 때만 입력란에 표시합니다. 총급여는 연봉에서 비과세 급여를 제외한 연간 금액으로 안내하며, 원 단위 정수 0~9,999,999,999원을 허용합니다. 미입력 목표금액은 ‘—’, 저장한 0원의 목표금액은 ‘0원’으로 구분합니다. 총급여 미입력 여부에 따라 별도 안내 행을 추가하지 않아 연도를 바꿔도 목표금액 카드의 구성과 높이를 유지합니다. 입력 창에서도 목표금액을 미리 보여주지만 ‘저장’을 눌러야 해당 연도에 반영합니다. 저장 실패 시 입력값을 유지하고 다시 시도할 수 있으며, 저장 중 중복 제출과 창 닫기를 막습니다.

연말정산 화면은 맨 아래 여백을 12, 연도 선택 행과 월 격자 사이 간격을 8로 두어 불필요한 세로 스크롤을 줄입니다. 1~12월은 구분선 없이 월 이름을 작은 회색 글자(12·굵기 500), 입력된 금액을 진한 글자(13·굵기 700)로 구분하고 사이 간격은 8로 둡니다. 미입력은 기본 회색 ‘-’를 유지하며 비교용 구분선 분기와 스타일은 제거합니다. 실제로 확정한 월만 흰 배경·두께 1의 연한 파란 테두리로 표시하고 금액은 기존 기본 글자색을 유지합니다. 테두리 공간을 기본 카드에도 미리 확보해 크기와 내용 위치는 동일하게 유지합니다. 1~3월의 디자인 비교용 임시 확정 표시는 제거하며, 월 버튼의 화면 읽기 안내에도 확정 여부를 포함합니다. 확정은 입력 완료 표시이며 입력을 잠그지 않습니다. 목표금액 카드와 월별 칸의 크기·월 행 사이 간격은 유지하며, 작은 화면이나 큰 글자에서 내용이 넘치면 스크롤로 전체를 확인할 수 있습니다.

목표금액 카드는 위쪽 여백 12·아래쪽 여백 8로 하단 버튼의 터치 영역을 고려해 균형을 맞춥니다. ‘목표금액 / 잔여금액’을 두 열로 나란히 표시하고, 목표금액과 잔여금액은 모두 22·굵기 700·행간 28로 맞추고 기존 파란색·회색 구분을 유지합니다. 라벨은 12 크기로 간결하게 구성합니다. 기준 설명과 같은 하단 행 오른쪽에 ‘연봉 입력’(미등록) 또는 ‘연봉 수정’(등록 후) 버튼을 표시합니다. 고정비·결제수단 등록 버튼과 같은 공통 CompactActionButton의 주요 스타일을 재사용해, 연한 파란 배경·파란 글자와 아이콘·모서리 10을 적용하고 작은 크기 옵션으로 보이는 높이 28·아이콘 12·글자 12를 적용합니다. 누르는 높이는 44 이상을 유지하며, 하단 설명은 ‘총급여의 25% / 사용금액 소득공제 기준’ 두 줄로 나누고 버튼은 같은 행 오른쪽에 유지합니다. 입력 창의 총급여 정의와 기존 연도별 저장 동작을 유지하며, 연봉 이력 조회 기능을 뜻하지 않습니다. 잔여금액은 목표금액에서 입력한 월들의 공제 대상 사용액 합계를 뺀 값이며, 목표 이상을 입력하면 0원으로 표시합니다. 연봉 미등록 시에는 ‘—’로 표시하고, 등록했지만 아직 입력한 월이 없으면 목표금액과 같습니다. 입력하지 않은 월의 실제 사용액은 추정하지 않습니다. 기준 설명은 카드 아래쪽에 두고, 카드 다음에 연도 선택과 3열 × 4행 월 격자를 배치하며 별도의 ‘월별 사용금액’ 제목은 표시하지 않습니다. 각 칸에는 선택 연도의 1~12월과 해당 월의 금액 영역을 배치합니다. 미입력 월은 짧은 ‘-’, 저장한 0원은 ‘0원’으로 구분하며 화면 읽기 안내에는 미입력 상태를 유지합니다. 월을 누르면 같은 연도·월의 사용금액 모달을 열고 저장한 값을 다시 수정할 수 있습니다. 조회 중·실패·저장 중에는 월 입력을 열지 않으며, 연도를 바꾸면 이전 연도 모달을 닫습니다. 카드 밖의 긴 소득공제 설명 문구는 표시하지 않습니다. 안내 문구는 공통 캡션의 위쪽 여백을 제거하고 물음표와 같은 줄 높이를 적용해 세로 중앙을 맞춥니다. 목표금액은 총급여 × 25%로 계산하며 원 미만이 생기면 소수점까지 유지합니다. 설명은 ‘총급여의 25%’와 ‘사용금액 소득공제 기준’을 두 줄로 표시하며, 둘째 줄의 ‘사용금액 소득공제 기준’ 바로 옆에 세로 중앙을 맞춘 물음표 버튼을 누르면 공제율 안내 모달을 엽니다. 총급여 입력 전에도 안내를 볼 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7794&mi=2468), [국세청 총급여 정의](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7871&mi=6594).

DB 버전 16에서는 `annual_tax_settings`에 연도(`year`, 기본키)별 총급여(`grossSalary`)만 저장하고 목표금액은 계산해 표시합니다. 다른 연도의 값을 복사하거나 덮어쓰지 않으며, 기존 결제수단·고정비·월 내역·혜택·이력을 유지합니다. 신규 설치와 버전 15 이하의 이전 경로 모두 같은 테이블을 생성하고, 이전 실패 시 테이블 생성과 버전 변경을 되돌립니다. 연말정산 조회도 연도·데이터 갱신 번호·재시도·저장·화면 활성 상태를 확인해 오래된 응답을 숨기고 다른 보기에서는 조회를 중지합니다.


연말정산 연도 선택 행 오른쪽의 공통 ‘카드 선택 · N개’ 회색 보조 버튼에서 해당 연도에 포함할 신용·체크카드를 선택합니다. 버튼은 연봉 입력·수정과 같은 small 크기(보이는 높이 28·아이콘 12·글자 12)를 사용하며 누르는 높이 44는 유지합니다. 별도의 ‘연말정산 카드 N개’ 행은 표시하지 않으며, 좁은 화면·큰 글자·다른 연도의 되돌림 버튼으로 공간이 부족하면 공통 연도 선택 행 안에서 줄바꿈합니다. 선택은 카드 ID 목록으로 관리하며 다른 연도와 분리합니다. 월별 입력 순서는 ‘현금영수증 → 지역카드(이음카드 등) → 체크카드별 금액 → 신용카드별 금액’입니다. ‘현금·지역카드 / 체크카드 / 신용카드’ 제목과 입력칸을 각각 공통 카드와 같은 흰색 배경의 둥근 영역 안에 묶습니다. 현금영수증·지역카드 입력은 첫 영역에 함께 둡니다. 상단 입력 안내와 지역카드 아래 설명·중복 입력 안내는 표시하지 않습니다. 영역 간격·안쪽 여백·입력칸 사이 간격은 12로 줄이고, 영역 제목은 16 크기로 표시합니다. 연말정산 사용금액은 공통 Field의 가로 배치 옵션을 사용해 왼쪽 라벨·로고와 오른쪽 금액 입력칸을 같은 행에 배치하며, ‘원’은 입력칸 옆에 표시합니다. 아이콘과 카드명 사이는 6 간격으로 붙입니다. 금액은 오른쪽 정렬하고 입력 높이는 최소 48을 유지합니다. 화면 폭과 글자 배율에 따라 공간이 부족하면 라벨과 입력칸을 두 줄로 전환하며 긴 카드명은 줄바꿈합니다. 전체 지우기·오류 안내·포커스 이동·저장 동작은 유지합니다. 해당 카드가 있는 영역만 표시하며 구분선은 사용하지 않습니다. 카드명 앞에는 기존 기관 로고를 표시하고 하단에는 기관명·카드 종류를 반복하지 않습니다. 저장된 기관명으로 기존 로고를 찾으며, 삭제·선택 해제 안내와 저장 금액은 유지합니다. 카드명·기관 로고·종류별 영역으로 구분하고, 같은 이름의 카드도 ID별로 분리합니다. `src/data/tax-spending-types.ts`의 고정 코드는 현금영수증·지역카드와 이전 체크·신용카드 합계 보존에 사용하며, 카드별 금액은 결제수단 ID를 참조합니다. 각 금액은 0~9,999,999,999원의 정수이며 빈 입력은 명시적으로 저장할 때 0원으로 처리합니다. 저장된 금액이 0원이면 입력칸은 빈 상태로 열고 회색 0은 안내 표시로만 보여 바로 새 금액을 입력할 수 있게 합니다. 0원이 아닌 저장 금액은 그대로 채웁니다. 입력 영역과 16 간격을 둔 하단에 회색 ‘합계’ 라벨과 오른쪽 진한 금액을 한 행으로 표시하고, 12 간격 아래에 공통 ButtonGroup으로 ‘저장’(왼쪽 보조)·‘확정’(오른쪽 주요) 버튼을 나란히 둡니다. 저장은 금액을 미확정 상태로 보관하고, 확정은 현재 입력한 금액과 확정 상태를 함께 저장합니다. 확정한 월을 다시 열면 저장 버튼을 제공하며 직접 수정한 금액과 확정 상태를 함께 유지합니다. 두 동작에 같은 금액 검증·중복 실행 방지·저장 실패 처리를 적용하며, 저장 중에는 입력과 버튼을 비활성화합니다. 별도의 배경이나 박스를 추가하지 않으며, 긴 금액·큰 글자에서는 합계 행이 줄바꿈할 수 있습니다. 입력 중 월 합계를 보여주고, 저장을 누르기 전에는 DB를 변경하지 않습니다. 공통 숫자 입력·전체 지우기·오류 표시·모달 스크롤·저장 버튼을 사용하며, 실패 시 입력값을 유지하고 중복 저장을 막습니다. 지역카드는 다른 항목과 중복되지 않은 실제 사용액을 입력하는 항목입니다. 공제 대상 여부를 자동 판정하거나 결제수단·고정비에서 자동으로 가져오지는 않습니다.

DB 버전 17은 `monthly_tax_spending` 테이블에 연도·월을 복합 기본키로 두고 네 사용금액을 저장합니다. 네 기본 금액은 UPSERT로 변경하며, 다른 연도·월과 연봉을 유지합니다. 월 합계와 잔여금액은 파생값으로 계산하고 저장하지 않습니다. 기존 버전 16의 연봉·결제수단·고정비·월별 이력은 그대로 보존하고, 새 설치와 기존 설치에 동일한 테이블을 추가합니다. 마이그레이션 실패 시 새 테이블과 버전 변경을 함께 되돌리고 재실행할 수 있습니다. 연간 조회는 기존 DB 대기열에서 연봉과 해당 연도의 월별 입력을 함께 불러오고, 저장 후 갱신 번호를 통해 합계와 잔여금액을 다시 표시합니다.

DB 버전 19에서는 `monthly_tax_spending`에 월별 입력 완료 여부인 `confirmed`를 추가합니다. 앱 모델은 boolean, SQLite는 기본값 0·허용값 0/1의 정수로 관리하며 연도·월별 금액·카드 상세와 같은 트랜잭션으로 저장합니다. 기존 월별 금액과 카드 ID·관계는 보존하고 모든 기존 월의 상태는 미확정으로 이전합니다. 신규 설치와 기존 설치에 같은 제약을 적용하고, 이전 실패 시 컬럼 추가와 버전 변경을 함께 되돌려 재시도할 수 있습니다. 이전 호출부가 확정 값을 생략하면 신규 월은 미확정, 기존 월은 현재 상태를 유지합니다. 확정 여부는 합계 포함 기준이 아니므로 미확정 저장 금액도 기존처럼 연간 사용금액·잔여금액 계산에 포함합니다.


DB 버전 18은 `annual_tax_cards`에 연도별 선택 카드 ID와 순서를, `monthly_tax_cards`에 월별 카드 금액과 카드명·카드사·종류 스냅샷을 저장합니다. 월의 기본 금액과 카드별 금액을 하나의 트랜잭션으로 변경하며, 저장된 카드 내역의 누락·중복·다른 월 ID·미선택 신규 카드를 거부합니다. 카드 선택 해제는 기존 금액을 변경하지 않습니다. 결제수단 삭제 시 선택 관계만 제거하고 월별 카드 참조는 NULL로 바꾸며 금액·이름·행 ID는 보존합니다. 기존 월을 열면 현재 선택 카드와 해당 월의 저장 카드를 합쳐 보여주므로 삭제·선택 해제된 카드도 금액을 확인·수정할 수 있습니다. 카드 이름 변경은 저장 당시 스냅샷을 덮어쓰지 않습니다.

버전 17에서 이전할 때 사용자가 지정한 ‘오하Check’ 체크카드를 유일하게 찾으면, 모든 기존 월의 체크카드 합계를 그 카드의 월별 금액으로 연결하고 해당 연도의 선택 카드에 포함합니다. 공백·대소문자만 정규화하며 다른 카드에 임의로 배정하지 않습니다. 이전한 기본 체크카드 합계는 0으로 바꿔 중복 합산을 막고 현금영수증·지역카드·신용카드 합계와 월 총액은 유지합니다. 동일 이름이 여러 장이거나 카드가 없으면 금액을 기존 ‘카드 미지정’ 합계로 보존합니다. 연결할 수 없는 기존 신용카드 합계도 같은 방식으로 보존하며, 카드별로 직접 옮길 때 미지정 금액을 조정하도록 안내합니다. 새 테이블 생성·오하Check 연결·기존 합계 조정·버전 변경은 한 트랜잭션으로 처리하고 실패 시 전부 되돌립니다. 이후 재실행에는 이전을 반복하지 않습니다.

## 파일 구조

앱의 시작점은 `expo-router/entry`입니다. 예전 `App.tsx` 대신 아래 화면 파일을 수정합니다.

- `src/app/(tabs)/`: 홈, 고정비, 결제수단, 결산, 설정 화면과 하단 탭
- `src/components/expense-list-view.tsx`, `expense-calendar-view.tsx`: 고정비의 목록·캘린더 보기
- `src/components/annual-summary-view.tsx`, `interest-income-view.tsx`, `year-end-tax-view.tsx`: 결산의 고정비·이자·연말정산 보기
- `src/app/_layout.tsx`: 앱 공통 설정과 데이터 저장 초기화
- `src/components/`: 공통 화면 구성과 입력 폼
- `src/data/`: 데이터 모델과 SQLite 읽기·쓰기
- `src/hooks/`: 화면에 데이터를 공유하는 상태 관리
- `src/utils/`: 합계, 날짜 계산, 입력 검증

나중에 백엔드를 추가할 때는 화면과 분리된 데이터 읽기·쓰기 부분부터 변경할 수 있습니다.

DB 버전 12에서는 `isDeleted` boolean flag를 DB의 `0/1`로 관리해 고정비 삭제와 종료를 구분합니다. 종료는 마지막 반영 월까지 캘린더에 남기고 종료 목록에서 조회·재등록할 수 있습니다. 삭제는 진행 중·종료 목록 모두에서 제외하며, 이번 달까지의 기존 기록과 직접 입력한 실제 금액을 유지합니다. 진행 중 항목을 삭제하면 마지막 반영 월을 이번 달로 설정하고 다음 달 이후 자동 내역을 제거합니다. 이미 종료한 항목을 삭제할 때는 기존 종료 월과 이번 달 중 더 이른 월을 기준으로 자동 내역을 정리합니다. 이름이 같아도 ID로 처리하므로 다른 항목이나 재등록한 새 기간에는 영향이 없습니다.

재구독·다시 등록은 이전 이름·유형·금액·분류·결제일·현재 연결 결제수단을 입력 폼에 채웁니다. 기본 시작 월은 이번 달이며, 이전 마지막 반영 월이 이번 달 이후라면 그다음 달을 제안합니다. 새 시작 월은 이전 마지막 반영 월 이후여야 합니다. 새 ID의 항목으로 저장하므로 중단 기간은 비워 두고 이전 월 기록·금액 이력을 유지합니다. 삭제한 항목은 종료 목록에서 재등록할 수 없습니다.

월별 카드 이용금액 입력과 생활비 계산 기능은 취소되어 화면·입력 폼·계산·저장 API·연결 수정 코드와 전용 테스트를 제거했습니다. 신규 DB에는 `monthly_card_usage`를 만들지 않습니다. 이전 버전에서 이미 생성한 이 테이블과 입력값은 데이터 손실 없이 그대로 두며 현재 앱의 월 합계에 사용하지 않습니다. 월 합계는 고정비의 자동 금액과 직접 입력한 변동 금액만 더합니다. 월 내역의 기존 `methodId`와 카드 종류 스냅샷은 유지합니다.

## 카드별 월 혜택

카드 등록·수정에서 월 혜택 유형과 금액을 필수로 입력합니다. 유형은 `src/data/method-types.ts`의 `CARD_BENEFIT_TYPES`에서 `fixed`(고정) / `variable`(변동) 코드로 관리하고, 새 카드나 유형이 없는 기존 카드는 사용자가 직접 선택합니다. 두 유형 모두 0~999,999,999원의 정수 금액을 입력하며, 변동 유형의 금액은 월 예상액입니다. 혜택이 없으면 0원을 입력하며 유형 미선택이나 빈 금액으로 저장할 수 없습니다.

카드 목록과 상세에서 월 고정 혜택 또는 월 변동 혜택 예상액을 표시합니다. 신용카드와 체크카드 모두 지원하고, 통장에는 혜택을 저장하지 않습니다. 고정비 목록·결제수단의 고정 합계·정렬과 홈의 월 합계는 기존 지출 금액을 유지합니다. 고정비 캘린더에는 월 지출 합계·카드 혜택·혜택 반영 예상액을 작은 3줄 요약으로 표시합니다. 라벨은 회색을 유지하고 월 지출 합계와 예상·확정 혜택 금액은 같은 진한 회색으로 표시하며, 마지막 혜택 반영 예상액은 기존 파란색과 큰 크기·굵기로 강조합니다. 혜택은 항목명과 차감 기호로 구분하고, 주황색·초록색 구분은 캘린더의 미입력·미확정 동그라미에 사용합니다. 혜택은 고정비 연결 여부와 관계없이 카드별 한 번씩 합산하고, 혜택이 미등록된 기존 카드는 제외하며 0원은 반영합니다. 혜택 반영 예상액은 해당 월의 지출 합계에서 카드 혜택을 뺀 값이며 음수도 계산 그대로 표시합니다. 미입력 지출 건수와 날짜별 지출 합계는 기존 기준을 유지하고, 카드 혜택을 지출 내역으로 중복 등록하지 않습니다. 날짜별 고정비 내역은 첫 항목의 위쪽과 마지막 항목의 아래쪽 모서리만 혜택 정산과 같은 반경으로 둥글게 처리해 하나의 묶음으로 표시합니다. 내부 구분선과 행 높이·여백은 유지하며, 항목이 하나면 네 모서리를 모두 둥글게 표시합니다.

캘린더는 실제 말일(2월 28·29일, 30일, 31일)에 변동 카드 혜택이 미확정이면 동그라미를 날짜 아래에 표시합니다. 기존 변동비 미입력은 주황색, 카드 혜택 미확정은 초록색 동그라미로 구분하며 크기와 위치는 동일합니다. 두 항목 모두 입력이 필요하면 동그라미 두 개를 나란히 표시하고, 캘린더 하단 범례에 의미를 표시합니다. 말일 칸에 별도 혜택 텍스트는 추가하지 않습니다. 혜택을 확정하면 초록색 동그라미가 사라지고, 같은 날짜에 미입력 지출이 남아 있으면 주황색 동그라미는 유지됩니다. 지출이나 카드가 없는 달에도 말일을 선택하면 날짜별 내역 아래의 카드 혜택 정산을 확인할 수 있습니다. 변동 혜택 카드마다 실제 금액을 모두 입력하고 ‘혜택 확정’을 누릅니다. 미입력과 0원을 구분하며 0~999,999,999원의 정수만 허용합니다. 고정 혜택은 자동으로 포함하고, 카드의 월 예상액은 변경하지 않습니다. 변동 혜택 카드가 없는 경우에는 안내만 표시합니다. 말일 항목을 통한 입력은 현재 날짜와 관계없이 해당 월에 적용할 수 있습니다.

확정 전의 ‘예상 혜택’은 해당 월에 적용되는 카드별 고정 혜택과 변동 혜택 예상액을 합산합니다. 정산 화면에서는 미확정 카드의 월 예상액을 실제 금액 입력란의 기본값으로 채우며, 이미 확정한 카드는 0원을 포함한 저장된 실제 금액을 우선 표시합니다. 사용자가 실제 금액을 확인·수정하고 ‘혜택 확정’을 눌러야 저장됩니다. 월을 조회하거나 정산 화면을 여는 것만으로는 확정하지 않고, 저장하지 않고 닫으면 미확정 표시를 유지합니다. 처음 확정할 때 그달의 카드별 이름·기관·유형·예상액·실제액과 고정 혜택을 함께 보존하고, 합계 라벨을 ‘확정 혜택’으로 바꿉니다. 확정한 달에서는 당시 카드 구성을 유지하므로 나중에 카드를 추가·수정·삭제해도 확정 금액은 바뀌지 않습니다. 확정한 변동 금액은 말일 정산에서 다시 수정할 수 있으며, 다른 달이나 카드 기본 예상액에 영향을 주지 않습니다. 변동 지출의 실제 금액도 입력 후 다시 수정할 수 있습니다. 확정 금액 보존은 설정 변경으로 자동 덮어쓰지 않는다는 의미이며 직접 수정하는 동작은 허용합니다.

카드 혜택 유형·예상액을 수정할 때는 고정비와 같은 ‘변경 적용 월’을 선택합니다. 기본은 이번 달이며 이번 달 이후를 선택할 수 있습니다. 해당 월부터 새 혜택을 반영하고 이전 달의 미확정 예상액은 보존합니다. 같은 적용 월 및 그 이후의 예약된 혜택 설정은 새 변경으로 대체하며 이미 확정한 달은 유지합니다. 카드 이름·기관만 바꾸는 경우에는 금액 적용 시점을 앞당기지 않고 이번 달 이후의 표시 정보만 갱신합니다. 결제수단 목록은 마지막으로 저장한 카드 설정을 표시하고, 캘린더는 월별 적용 이력으로 계산합니다.

카드를 삭제하면 결제수단 목록과 기존 연결은 이전처럼 정리하되, 예상 혜택은 이번 달까지 유지하고 다음 달부터 제외합니다. 이전 달의 미확정 예상액과 모든 확정 내역은 보존합니다. 삭제한 카드의 이전 달 혜택도 말일에서 입력·재수정할 수 있습니다. 통장을 삭제해도 연결 카드의 혜택 이력은 유지합니다. 새 카드는 등록한 달부터 혜택을 반영합니다.

DB 버전 15에서는 `card_benefit_versions`에 카드 ID·적용 월별 혜택 설정과 표시 정보를 보존합니다. 카드 삭제와 함께 이력을 지우지 않으며, 다음 달에 혜택이 없는 설정을 남깁니다. 신규 설치와 이전을 지원하고, 기존 카드·월별 확정 혜택·고정비·지출 내역은 유지합니다. 기존 카드의 최초 등록 월은 알 수 없으므로 이전 시 저장되어 있는 설정을 `1000-01` 기준으로 보존해 기존 과거 월 표시를 유지합니다. 이미 유실된 과거 수정·삭제 이력은 추정해 복원하지 않습니다. 카드 설정과 이력 변경·삭제는 같은 트랜잭션으로 저장하고, 실패하면 함께 되돌립니다.

DB 버전 14에서는 `monthly_card_benefits`에 월과 카드 ID별로 확정 내역을 저장합니다. 카드 ID는 기존 `ledger_entries.methodId`처럼 당시 레코드의 ID를 보존하며 카드 삭제와 함께 제거하지 않습니다. 저장 계층에서 해당 월의 변동 카드 전체와 입력 ID·금액을 검증하고 고정·변동 혜택을 하나의 트랜잭션으로 확정합니다. 저장 중 실패하면 기존 확정 내역도 유지됩니다. 신규 설치와 기존 버전의 이전을 함께 지원하며, 기존 카드·고정비·정렬·월별 지출 내역은 변경하지 않습니다. 월 이동·보기 전환·저장 후에는 월과 데이터 갱신 번호를 확인해 이전 요청의 혜택이 다른 달에 표시되지 않게 합니다.

DB 버전 13에서는 결제수단에 `benefitTypeCode`와 `benefitAmount`를 추가합니다. 기존 통장·카드는 혜택을 추정하지 않고 미등록으로 이전하며 ID·연결 통장·카드 종류·정렬·고정비 참조·월 기록을 유지합니다. 이전은 트랜잭션으로 처리하고 실패 시 스키마와 버전을 되돌려 재시도할 수 있습니다. 저장 계층과 DB 제약 조건에서 유형·금액 쌍, 카드 전용 여부와 금액 범위를 검증합니다.

카드 등록·수정의 필수값은 화면과 저장 계층에서 모두 검증합니다. 통장 선택에 ‘미지정’ 옵션을 제공하지 않으며, 등록된 통장이 없으면 먼저 통장을 등록하도록 안내합니다. 기존 데이터와 통장 삭제 시의 참조 해제를 보존하기 위해 DB의 nullable 필드는 유지합니다. 기존 카드의 종류·연결·혜택 등 누락 값은 임의로 채우거나 삭제하지 않고, 다음 수정 시 필수 항목을 모두 입력해야 저장할 수 있습니다.

결제수단 폼은 필수 항목을 라벨의 별표로 표시하며 처음부터 오류를 노출하지 않습니다. 항목을 벗어나거나 저장을 누른 뒤 해당 입력칸·선택창·선택 버튼에 오류 테두리와 아이콘·짧은 안내를 표시하고, 정상 값으로 고치면 오류를 제거합니다. 저장 시에는 모든 오류를 함께 표시하고 화면상 첫 오류 위치로 스크롤·포커스를 이동합니다. 저장 버튼은 검증 오류 때문에 비활성화하지 않으며 저장 중에만 비활성화합니다. 저장 실패 안내는 폼 하단에 표시하고 입력값은 유지합니다.

## 공통 코드와 데이터 설계 기준

앞으로 추가하거나 수정하는 기능은 서버·DB 확장을 고려해 다음 기준을 기본으로 적용합니다. 저장 값은 UI 컨트롤 모양보다 데이터의 의미를 기준으로 결정합니다.

- **공통 선택 항목:** 셀렉트박스·라디오·체크박스에서 은행, 카드사, 유형, 상태 등 미리 정의된 항목을 선택할 때는 고정 코드를 저장합니다. 화면 표시명, 배열 순번, 번역된 문구를 저장 값으로 사용하지 않습니다.
- **단순 flag:** 사용 여부, 알림 켜짐처럼 참·거짓만 의미하는 값은 `boolean`을 사용합니다. SQLite에서는 `0/1`로 저장하고 데이터 읽기·쓰기 계층에서 변환합니다. 여러 상태를 나타내는 값은 코드로 관리합니다.
- **사용자 데이터 선택:** 직접 등록한 통장·카드 등 사용자마다 다른 항목은 해당 레코드의 ID로 참조합니다. 현재 `bankId`, `methodId`처럼 관계를 저장하고 DB에서 외래 키로 검증합니다.
- **다중 선택:** 여러 공통 항목을 선택하는 체크박스는 코드 배열로 표현합니다. DB에서는 필요에 따라 연결 테이블로 관리하고, 쉼표로 합친 표시명이나 배열 순번으로 저장하지 않습니다.
- **이름 규칙:** 코드 값은 소문자 `snake_case`를 사용합니다. 예: `bank_kb`, `card_samsung`, `bank`, `card`. 코드 목록 상수는 `BANK_PROVIDERS`처럼 대문자 `UPPER_SNAKE_CASE`를 사용합니다. 모델 필드명은 기존처럼 `providerCode`, `bankId` 등 `camelCase`를 유지합니다.
- **한곳에서 관리:** 코드·표시명·아이콘 정보는 `src/data/`의 도메인별 목록에서 관리하고, 화면은 해당 목록을 사용합니다. TypeScript 타입도 목록에서 유도하거나 공통 타입으로 정의해 허용 값을 제한합니다. 저장 시 지원하는 코드와 해당 분류가 맞는지 검증합니다.
- **서버·DB 연동:** 기관 같은 공통 목록은 코드 테이블과 외래 키로, 작은 고정 유형은 제약 조건으로 검증합니다. 추후 서버가 공통 목록을 제공하면 서버를 기준으로 목록을 관리하고, API·앱·DB가 같은 코드 값을 사용하도록 연결합니다.
- **기존 데이터 유지:** 표시명·아이콘 변경 시 코드는 유지합니다. 저장된 코드의 변경·삭제가 필요하면 데이터 이전과 기존 참조 처리를 함께 구현합니다. 미지원 코드가 들어와도 임의의 기본 코드로 바꾸지 않고 기존 값을 보존해 처리합니다.

현재 은행·카드사는 `src/data/providers.ts`와 `payment_providers`에서 이 방식으로 관리합니다. 위 규칙은 향후 개발 기준이며, 아직 없는 서버 API나 새 기능이 구현되었다는 의미는 아닙니다.

기능 변경 시 대체된 코드·스타일·가져오기와 실제로 사용하지 않게 된 라이브러리를 함께 정리합니다. 다른 기능이나 의존성에서 필요한 라이브러리는 유지합니다. UI 구성이나 조작 방식이 달라지는 작업은 구현 전에 선택지와 추천 구성을 설명하고 사용자와 방향을 정합니다.
